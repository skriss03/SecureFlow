SecureFlow on OpenShift: Developer Guide

SecureFlow is already running for your team. This guide shows how to scan the project you have cloned on your machine, from a terminal, from your IDE, from your build, from a Git hook or from a pipeline, and get a report link you can share.

secureflow scan

Your team's addresses

Type them once and every command on this page updates. Your platform team can fill these in before sharing the file. Nothing is sent anywhere, and your token is never asked for here.

How it fits together

Your machine does the reading, the shared server does the analysing. You never run the SecureFlow server yourself, and you don't need an AI key.

Your machineYou run secureflow scan in your cloned project.The command reads files locally and redacts secrets.
Upload over HTTPSSelected files and the dependency list go to the server with your team token.Source code is not compiled or run.
SecureFlow on OpenShiftAI rebuilds your architecture, rules score it, every dependency is checked for known CVEs.The AI keys live only on the server.
Report linkYou get a link and a pass/fail exit code.Same link on every rescan; kept for the retention period.

One-time setup (about 5 minutes)

You need two things from your platform team: the team token, and the server address and download folder shown at the top of this page.

  1. Install the secureflow command It is a single self-contained program. It needs no .NET, Java, Node or Python, and no admin rights. 
    Windows (PowerShell)irm https://artifactory.example.com/artifactory/generic-local/secureflow/install-cli.ps1 -OutFile install-cli.ps1
.\install-cli.ps1 -BaseUrl https://artifactory.example.com/artifactory/generic-local/secureflow -Server https://secureflow.apps.example.com
    macOS / Linuxcurl -fsSL https://artifactory.example.com/artifactory/generic-local/secureflow/install-cli.sh -o install-cli.sh
SECUREFLOW_CLI_BASE_URL=https://artifactory.example.com/artifactory/generic-local/secureflow SECUREFLOW_SERVER=https://secureflow.apps.example.com sh install-cli.sh
    The installer puts secureflow in ~/.secureflow/bin, adds it to your PATH, and saves the server address in ~/.secureflow/config.yml. If your team publishes the installer somewhere else, use that location instead.
  2. Save your team token Store it as an environment variable, so it never appears in a project folder or in Git. 
    Windows (PowerShell), once[Environment]::SetEnvironmentVariable("SECUREFLOW_TOKEN", "<your team token>", "User")
    macOS / Linux, add to ~/.bashrc or ~/.zshrcexport SECUREFLOW_TOKEN="<your team token>"
    Treat the token like a password. Don't put it in a repository, a ticket or a chat. If it leaks, ask the platform team to replace it.
  3. Open a new terminal and check everything A new terminal is needed so it picks up the new PATH and token. 
    secureflow --version
secureflow config
curl https://secureflow.apps.example.com/api/health
    • secureflow --version shows 0.1.0 and the folder ~/.secureflow/bin. If it shows another folder, an older copy is earlier on your PATH; remove it.
    • secureflow config lists every setting. server should be your team's address and token should show masked characters.
    • The health page should say "status":"ok" and "available":true under ai. If you can't reach it, check that you are on the company network or VPN.
That's the whole setup. From now on, every project on your machine is one command away.

Ways to run a scan

All of these run the same secureflow scan, so the report is identical. Pick whichever fits how you already work. You can use more than one.

TerminalIntelliJ · VS Code · Visual Studio · EclipseMaven · Gradle · npmGit hookCI pipeline
From any terminal Start here

Works the same in PowerShell, Command Prompt, Windows Terminal, bash, zsh and the macOS Terminal, for every tech stack.

  1. Go to the project you cloned 
    cd C:\code\orders-service
  2. Preview what would be sent (optional, sends nothing) 
    secureflow scan --dry-run
    You see the list of files, the dependencies found, and how many secret values were redacted.
  3. Scan 
    secureflow scan --open
    The command prints three labelled steps, then the scores and the link. --open opens the report in your browser. It usually takes one to a few minutes. 
    [1/3] Reading the project on this machine ...
[2/3] Uploading 39 files and 15 dependency versions to https://secureflow.apps.example.com as 'orders-service@main'
[3/3] Server is analysing: architecture model (AI), resilience + STRIDE rules, CVE check

From your IDE No plugin needed

Every IDE has a built-in terminal that opens in your project folder, so the command is the same as above. Optionally, save it as a one-click action.

IntelliJ IDEA, PyCharm, WebStorm, Rider

  • Terminal: press Alt+F12 (or View → Tool Windows → Terminal) and run secureflow scan --open.
  • One-click: Run → Edit Configurations → + → Shell Script. Set Execute to Script text with secureflow scan --open, and the working directory to the project folder. Name it "SecureFlow scan". Run it with the green button.
  • Maven or Gradle projects: add a Maven run configuration with the command line secureflow:scan, or run the secureflow Gradle task from the Gradle tool window. See "Build tool" below.
  • npm projects (WebStorm): after adding the script (below), run secureflow from the npm tool window.

Visual Studio Code

  • Terminal: press Ctrl+` and run secureflow scan --open.
  • One-click: create .vscode/tasks.json in the project, then use Terminal → Run Task → "SecureFlow scan". 
    {
  "version": "2.0.0",
  "tasks": [
    {
      "label": "SecureFlow scan",
      "type": "shell",
      "command": "secureflow scan --open",
      "problemMatcher": []
    }
  ]
}

Visual Studio (.NET)

  • Terminal: View → Terminal (Ctrl+`) opens a Developer PowerShell in the solution folder. Run secureflow scan --open.
  • One-click: Tools → External Tools → Add. Title: SecureFlow scan. Command: secureflow. Arguments: scan --open. Initial directory: $(SolutionDir). Tick Use Output window. It then appears in the Tools menu.

Eclipse / Spring Tools

  • Maven projects: right-click the project → Run As → Maven build… → Goals: secureflow:scan. Eclipse remembers it as a launch configuration.
  • Any project: Run → External Tools → External Tools Configurations → Program. Location: ${env_var:USERPROFILE}\.secureflow\bin\secureflow.exe (or the full path to secureflow on macOS / Linux). Working directory: ${project_loc}. Arguments: scan --open.
If the IDE's terminal says secureflow is not recognised, restart the IDE. IDEs read the PATH when they start, so one that was open during install does not see it.

Before you push: a Git hook Optional

Catch Critical findings before they reach the remote. A pre-push hook runs the scan and stops the push if the gate fails. It works on your clone only and does not change the repository.

.git/hooks/pre-push  (macOS / Linux / Git Bash on Windows; save without an extension)#!/bin/sh
secureflow scan --fail-on critical || {
  echo "SecureFlow gate failed. Fix the findings, or push with: git push --no-verify"
  exit 1
}
# macOS / Linux: make it executable
chmod +x .git/hooks/pre-push
A scan takes a minute or more, so a pre-push hook is best for teams that accept that wait. Use --no-wait if you only want the upload without blocking the push.
In your CI pipeline Team gate

The pipeline runs the same command on every pull request, so the gate applies to everyone. Keep the token as a pipeline secret and the server address as a pipeline variable. The exit code decides pass or fail: 0 pass, 2 findings reached your threshold, 1 the scan could not run.

GitHub Actionsenv:
  SECUREFLOW_SERVER: ${{ vars.SECUREFLOW_SERVER }}
  SECUREFLOW_TOKEN:  ${{ secrets.SECUREFLOW_TOKEN }}
steps:
  - uses: actions/checkout@v4
  - run: |
      curl -fsSL "https://artifactory.example.com/artifactory/generic-local/secureflow/0.1.0/secureflow-linux-x64" -o secureflow
      chmod +x secureflow
      ./secureflow scan --fail-on critical --out secureflow-report.md
Jenkins (declarative)environment {
  SECUREFLOW_SERVER = 'https://secureflow.apps.example.com'
  SECUREFLOW_TOKEN  = credentials('secureflow-token')
}
stages {
  stage('SecureFlow') {
    steps { sh 'secureflow scan --fail-on critical' }
  }
}

The same pattern works in Azure DevOps and GitLab CI: set the two variables, download or preinstall the command, and run secureflow scan --fail-on critical. A ready GitHub Actions file is in samples/ci/secureflow-gate.yml.

In CI the project key defaults to repository@branch, so each branch gets its own report and a pull request does not overwrite the report for main.

"Parsed exactly" means no AI and the same result every time: the same system drawn in Visio, Mermaid or draw.io gives the same findings. Put replica counts, protocols and auth in your labels (x2, HTTPS, JWT, no auth) and draw zones as boxes around services for the most precise report. Dashed arrows are read as asynchronous.

Daily workflow

  1. Scan before you open a pull request 
    secureflow scan --open
  2. Read the report, highest severity first Each finding shows the evidence (file and line), why it matters and how to fix it. For a fix proposal, open the finding and choose Propose fix. CVE findings state the version to upgrade to.
  3. Fix, then scan again 
    secureflow scan
    The report keeps the same link and adds a point to the score history. Findings you fixed are marked Fixed or drop off the list, and the scores update.
  4. Mark what you accept If a finding is a conscious trade-off, mark it Accepted in the report. It stays accepted on later scans and no longer counts toward the gate.
  5. Paste the link in your pull request Reviewers open the same report you did, with no tool to install.

For the best CVE results, commit your lockfile and pin exact versions. Version ranges (^1.2, >=2.0) and versions decided by a parent or BOM can't be checked, so SecureFlow skips them rather than guess.

A monorepo is scanned in one run from its root, and the report shows one model across the services. To get a separate report for one module, use secureflow scan --path services/orders.

Sharing and retention

QuestionAnswer
Who can open my report link?Anyone who can reach the server, typically colleagues on the company network. Opening a report does not need a token; running a scan does. (Your platform team can require a token for reading too.)
How long is it kept?For the retention period after its last update, 30 days by default. Scanning again resets that clock. Download the report as Markdown with --out report.md, or print it to PDF from the Report tab, if you need a permanent copy.
Will a rescan change the link?No. The project is identified by repository and branch (orders-service@main), so rescans update the same report and keep its history.
How do I show up on my team's dashboard?Add --group "Payments Team", or put group: Payments Team in a .secureflow.yml file at the repository root. The group is created if it doesn't exist.
Can two people scan the same branch?Yes. They update the same report. If a scan is already running, the second command follows it instead of starting another.

What leaves your machine

  • Only selected files: deployment files, configuration, a limited number of source files that show how services connect, and the README. Not your whole repository.
  • No secrets: values for keys such as password, secret, token, apikey and connection strings are replaced with ***REDACTED*** on your machine, before upload. Private keys, JWTs and passwords inside URLs are also removed. Line numbers are kept, so findings still point to the right line.
  • The dependency list: names and versions only, taken from your manifests and lockfiles.
  • Over HTTPS to the team server, with your token. Nothing is sent to a third party except by the server: the AI service your organisation configured, and the public vulnerability database (OSV) for CVE lookups.
  • You are in control: run secureflow scan --dry-run to see the exact list first.
Redaction recognises common key names. If your project names a secret differently (for example gateway.credentials is covered, but magic_phrase is not), check the dry run, and add the name with redaction.keyPattern in .secureflow.yml.

Settings

Each setting is looked up in this order, and the first one found wins:

  1. The command-line option, for example --fail-on high
  2. An environment variable, for example SECUREFLOW_FAIL_ON=high
  3. .secureflow.yml in the repository
  4. ~/.secureflow/config.yml in your user folder
  5. The built-in default

Personal settings, ~/.secureflow/config.yml. Set by the installer; add the token here only if you can't use an environment variable.

server: https://secureflow.apps.example.com
# token: <your team token>

Project settings, .secureflow.yml committed in the repository. Never put the server address or token here.

name: orders-service
group: Payments Team

Troubleshooting

You seeWhat it means and what to do
cannot reach SecureFlow at https://...Check you are on the company network or VPN, then open https://secureflow.apps.example.com/api/health in a browser. Confirm the address with secureflow config. If your company uses a web proxy, set HTTPS_PROXY (macOS / Linux) or configure the Windows proxy, as for any other tool.
server returned 401 UnauthorizedThe token is missing or wrong. Check that secureflow config shows a masked token, that you opened a new terminal after saving it, and ask the platform team to confirm the token is current.
Certificate or TLS errorYour machine does not trust the company's certificate authority. Ask IT to install the root certificate in your system trust store. As a last resort for a test server only, --insecure-skip-tls-verify turns the check off. Never use it against a production server.
scan failed on the server with an AI error, or server returned 503The AI service behind SecureFlow is down, rate-limited, or its key has a problem. This is not something you can fix on your machine; send the platform team the report link and try again in a few minutes. If the server is set to accept scans without AI, you instead get a CVE-only report that says "Architecture not analysed".
server returned 413 (digest too large)The upload is above the server's size limit. Exclude generated or vendored folders with ingest.extraSkipDirs in .secureflow.yml, or ask the platform team to raise the limit.
A scan of this project is already runningSomeone (maybe you, or the pipeline) is scanning the same repository and branch. The command follows that scan; wait for it to finish.
The scan times outLarge repositories and a busy AI service can take longer than 15 minutes. The scan keeps running on the server. Open the link it printed, or raise --timeout-seconds.
No CVEs, but you expected someVersions must be written in a manifest or lockfile. Commit the lockfile or pin the version, then check the dry run shows "Resolved N pinned dependencies".
The report misses a service or callThe file that shows it wasn't picked up. Run --dry-run, then add its path or a code pattern in .secureflow.yml (ingest.extraPriorityPatterns, ingest.extraWiringSignals).
secureflow not recognisedOpen a new terminal (and restart your IDE). If it still fails, run the installer again.
secureflow --version shows another folderAn older copy is earlier on your PATH. Remove it, for example dotnet tool uninstall -g secureflow.cli.

For the platform team: rollout checklist

Hand developers this page after the following is in place. Details are in docs/developer-integration.md and deploy/openshift/.

  1. Server is live: the SecureFlow pod is running on OpenShift behind a TLS Route, and /api/health shows "status":"ok" and "available":true for the AI provider.
  2. Report links are correct: SecureFlow__PublicBaseUrl is set to the Route address, so links in scan output open from any laptop.
  3. Tokens are issued: SecureFlow__Auth__Enabled=true and one token per team in SecureFlow__Auth__Tokens__N, from an OpenShift Secret, never the ConfigMap. Replace a token by editing the Secret and restarting the pod.
  4. Retention is set: SecureFlow__Retention__Days (30 by default) and a persistent volume mounted at /data, so reports survive restarts.
  5. Client files are published: the secureflow-<os>-<arch> programs under <version>/, plus install-cli.ps1 and install-cli.sh, in an Artifactory generic repository. Publish the Maven and Gradle plugins, the npm package and the Python package to their repositories if teams want build-tool integration.
  6. This page is personalised: type the server and Artifactory addresses in the box at the top, then share the file. It remembers them in your browser.
  7. Reachability: developers' laptops and the CI runners can reach the Route; the cluster can reach the AI service and api.osv.dev (or an internal mirror set with DependencyScan__OsvBaseUrl).
