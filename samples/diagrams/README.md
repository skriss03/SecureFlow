# Sample diagrams: one system, every tool

Every file here describes the same system, **NorthBank Payments**: a customer and an external card network on the internet, an API gateway in a DMZ, and in a private network:
- a payments API
- a single-instance fraud service
- a single SQL database
- a settlement queue and worker
- Key Vault and monitoring

It has deliberate flaws:
- single points of failure (database, fraud service, worker)
- synchronous calls with no timeout
- an unauthenticated internal call (Payments API → Fraud Service, "HTTP no auth")

Upload any of them (web UI → *Diagram from any tool*, or `secureflow diagram <file>`). The structured formats all give **the same model and the same rule findings** (34 findings, Resilience 43, Security 74 from the rules), which is the point: the analysis doesn't depend on the drawing tool. With an AI provider configured, the AI review then adds a few contextual findings on top; those can differ slightly from run to run, so final scores may move by a few points.

## How these were made

These files were **generated by our script, not exported from each tool**. They use each tool's real file format, from one definition of the system, so they all describe the same architecture:

- `scripts/make-sample-diagrams.py` writes the draw.io, Mermaid, PlantUML, Structurizr, Visio, Excalidraw, Gliffy and SVG files.
- `scripts/render-sample-diagrams.ps1` renders the SVG to PNG and PDF with a headless browser (Edge or Chrome), and writes the editable draw.io PNG.

To change the architecture, edit `NODES` / `EDGES` in the Python script and run both scripts again.

The AI-read files (SVG, PNG, PDF) give an analysis close to the others but not guaranteed identical: the AI is reading a picture or markup, not a structure. Where it isn't sure, it lists assumptions.
