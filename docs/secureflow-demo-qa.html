SecureFlow Demo Q&A Sheet

Likely questions from leadership and developers, with short, honest answers. Numbers below come from our own test runs.

30-second pitch. A developer runs one command, secureflow scan, in their cloned project. SecureFlow rebuilds the system's architecture from the code and configuration, scores its resilience and security, checks every dependency for known vulnerabilities, and gives back a report link that the whole team can open. It works the same for Java, .NET, Python, Angular, React and Node, and it can fail a build when serious findings are open.

Leadership questions

What problem does this solve?
Threat modelling and resilience reviews are manual, done once, and usually late. SecureFlow does a first pass in minutes, on any repository, every time the code changes, so risks show up before release and not after an incident.
How is it different from the scanners we already have?
Most scanners look at code or libraries. SecureFlow looks at the system: which services call which, what has no timeout or circuit breaker, which database is a single point of failure, and what goes down if one component fails (blast-radius simulation). It also checks dependencies for known CVEs. It complements code scanners; it does not replace them, and it does not do code-level analysis (SAST).
Can we trust AI-generated findings?
The AI only rebuilds the architecture model. The findings come from 26 fixed rules (14 resilience, 12 security) that run the same way every time, and each one cites the file and line it came from. CVEs come from a public vulnerability database (OSV), not from the AI. Extra AI observations are labelled as such, with lower confidence, and every assumption is listed.
What does it cost to run?
The main cost is AI usage: each scan makes a few AI calls (build the model, review the findings). We have not measured a cost per scan yet; Foundry's usage view will show it after the pilot. Cost is controlled because scans only run on request, need a team token, and identical re-scans can replay from a local cache. Say: "We will measure it in the pilot." Don't quote a figure.
What did it find in your tests?
On the open-source libfintx banking library: Resilience 45 (D), Security 23 (F), 64 open findings (4 Critical, 25 High), 14 of them CVEs. On our deliberately flawed Spring sample it found Log4Shell (CVE-2021-44228) as Critical.
How long does a scan take, and does it slow developers down?
Typically a few minutes, mostly the AI step. It never runs unless the developer starts it, and the optional Maven, Gradle and npm plugins are not part of a normal build. Failing a build on findings is opt-in (--fail-on); it is off by default.
What does rollout take?
Platform team: deploy one container to OpenShift (image, Route, storage and settings are prepared), publish the client program to Artifactory, issue team tokens. Developers: a 5-minute one-time install, then one command. Be clear: this is proven end to end on a local server. The OpenShift files are written but not yet tested on a real cluster.
Does it replace human threat modelling?
No. It gives reviewers a head start, a consistent baseline and a model to discuss, so their time goes to judgement rather than drawing diagrams.
What would you build next?
Candidates, not commitments: single sign-on instead of shared team tokens, a database so the server can run more than one copy, pull-request comments with the report link, an IDE plugin, and a usage and cost dashboard.

Security and risk questions

What leaves the developer's machine?
Only selected files (deployment, configuration, a limited number of source files that show how services connect, the README) and a list of dependency names and versions. Secret values (passwords, tokens, keys, connection-string passwords, private keys, passwords inside URLs) are replaced with ***REDACTED*** before upload. Nothing is compiled or run. secureflow scan --dry-run shows exactly what would be sent.
Where does the AI run and who sees the code?
The server calls the AI service the organisation configured; in our setup that is Claude through Microsoft Foundry. Only the server talks to it. Developers never see the AI key. For data-retention and training terms, point to the Foundry / Azure agreement rather than answering from memory.
What is the "team token"? Is it the AI key?
No. The AI key stays on the server, in an OpenShift Secret. The team token is a password for the SecureFlow server that says "this request comes from an authorised team". It allows starting scans; reading a report link does not need it by default. One token per team means one team's token can be replaced without affecting the others. Honest limit: today it is a shared token; the server checks it but does not record which team used it. SSO would be the upgrade.
Who can see a report?
Anyone who can reach the server and has the link, typically colleagues on the company network. The platform team can require a token for reading as well (a setting). Reports are deleted after the retention period, 30 days by default.
Is downloading and running an install script safe?
The guide downloads the script to a file first so it can be read before it runs, and it runs without admin rights. It does not use the "download and run in one step" pattern.

Developer questions

What do I need to install?
One small program, secureflow. No .NET, Java, Node or Python is needed to run it, and no admin rights.
Does it upload my whole repository or run my code?
No to both. See "What leaves the machine" above. Use --dry-run to check.
Which technologies are supported?
Full: Java / Spring (Maven and Gradle), .NET, Python (FastAPI, Flask, Django), Angular, React, Node.js. Partial: Go (deployment files and go.mod only). Any other stack gets an architecture report from its Docker, Kubernetes and Terraform files, but no CVE check.
Can I use it from my IDE?
Yes, from the IDE's built-in terminal (IntelliJ, VS Code, Visual Studio, Eclipse), or as a saved one-click action. No IDE plugin is required.
Why did it miss a vulnerability I know about?
It only checks versions written in a manifest or lockfile. Ranges (^1.2) and versions set by a parent or BOM cannot be known, so they are skipped rather than guessed. Commit the lockfile or pin the version.
What if a finding is a deliberate trade-off?
Mark it Accepted in the report. It stays accepted on later scans and stops counting toward the build gate.
Does the report link change when I scan again?
No. A project is identified by repository and branch, so a re-scan updates the same report and keeps the score history.

Be careful with these claims

Safe to say
  • "One command works for every stack we support."
  • "Secrets are removed on the developer's machine before anything is uploaded."
  • "Findings come from fixed rules with file and line evidence; the AI builds the model, and CVEs come from a public database."
  • "Built for OpenShift and proven end to end on a local server. On OpenShift, the only change for a developer is the server address and the token."
Don't claim
  • That it has been tested on OpenShift, or at what scale. It hasn't yet.
  • A cost per scan, or exact scan times. Say "a few minutes" and "we will measure it".
  • That it replaces code scanners or human reviewers.
  • Single sign-on, per-user audit or high availability. None of these exist yet: it is one server copy with file storage and shared team tokens.
  • That every language is fully covered. Go is partial, and unsupported stacks get no CVE check.

Suggested 7-minute flow

  1. Problem (30 s): manual, late, security-only threat modelling.
  2. One command (60 s): secureflow scan --dry-run, then show what would be sent and the redaction.
  3. Scan (90 s): secureflow scan --open; narrate the three labelled steps.
  4. Report (90 s): scores, a Critical finding with file and line, then the CVE list.
  5. Blast radius (45 s): pick a database, Simulate failure, show what goes down with it.
  6. Fix and rescan (60 s): propose a fix, apply it, show the score move and the same link.
  7. Gate and rollout (45 s): --fail-on critical, IDE and pipeline use, token and OpenShift in one slide.
